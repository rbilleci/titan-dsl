# API overview

Titan DSL is a standalone Java library for typed SQL construction and rendering.
Start with the [README](../README.md#contents) for installation, runnable
recipes, JDBC integration, and behavior that depends on the rendering path.

DSL runtime types live in `titan.dsl`; the separate codegen and plugin modules
use `io.titan.catalog`, `io.titan.introspect`, and `io.titan.gradle`.
HTML API documentation is generated by
`./gradlew javadoc` into each module's `build/docs/javadoc/` directory.

| Area | Main API | What it provides |
| --- | --- | --- |
| Query context | `DSL.using(SqlDialect)`, `DSLContext` | Immutable, connection-free configuration; SELECT/DML/WITH factories create fresh builders supporting `render()` without repeating the dialect. |
| Schema descriptors | `Table<R>`, `View<R>`, `TableLike<R>`, `Column<T>`, `SQLType`, `Nullability` | Typed names and schema intent; no database introspection or DDL execution. |
| Schema generation (companion build tooling) | `SchemaIntrospector`, `CatalogGenerator`, `titanGenerate` | Derive descriptors, records, keys, and enums from database metadata; see the [setup](../README.md#generate-your-java-catalog-from-the-schema). These are not classes in the DSL JAR. |
| Keys and aliases | `UniqueKey`, `ForeignKey`, `Table.as`, `AliasedTable.col` | Relationship descriptors and explicitly qualified references. |
| Conditions | Column comparisons, `Condition.and/or/not` | Composable predicates, including null and IN-list handling. |
| SELECT | `DSL.select`, `DSL.selectFrom`, `SelectBuilder` | Filtering, projection, distinct, ordering, pagination, and joins. |
| Reporting | `count/sum/avg/min/max`, grouping helpers, window helpers | Aggregate, grouping-set, ranking, and frame SQL construction. |
| Composition | `name/with/withRecursive`, `union/unionAll/intersect/except`, `exists/notExists/scalar` | Named stages and nested/combined queries; binding behavior varies by helper. |
| DML | `insertInto`, `update`, `deleteFrom` | Values, batch VALUES, INSERT SELECT, upsert, and RETURNING forms. |
| Automatic filters | `Filter`, `FilterPolicy`, `FilterPath.via`, `Scope`, `TableRef`, `DSLContext.filters/scoped/unscoped` | Catalog-validated row filters added at render time to SELECT/UPDATE/DELETE; foreign-key paths render as correlated EXISTS. See the [README section](../README.md#automatic-filters). |
| Rendering | `render()`, `toSql()`, `ParameterizedSql`, `BindValue` | Use the query context's dialect; explicit-dialect overloads remain per-call overrides. Static unconfigured queries need `render(SqlDialect)`. |
| Typed projections | `SelectBuilder1..10`, `Tuple1..10` | Bounded typed projection shapes. |
| Metadata | `@StoredProcedure`, `@StoredFunction`, `@Trigger`, `@ScheduledJob`, `@SQL`, `@SecurityDefiner` | Annotations for custom tooling; no database action by themselves. |

The library does not execute queries. Fetch/execute-named convenience methods
return SQL or integration placeholders, not JDBC results. See the
[method behavior table](../README.md#typed-projections-and-convenience-methods).

`fetchInto(recordType)` validates projection width, simple identifier-shaped
projected names, and case-insensitive/snake-case-to-camel-case record matching.
It does not instantiate or populate records. Callback-shaped `forEach`
overloads validate shapes but do not execute callbacks over database rows.

Dialect selection does not imply universal SQL compatibility. Review the
[composition and binding boundaries](../README.md#composition-and-binding-boundaries),
[dialect limits](../README.md#dialect-and-safety-limits), and
[security guidance](../SECURITY.md).
